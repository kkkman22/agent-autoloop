# Jira 更新 → 钉钉群 @创建人 通知

## Context

分支 `feature/jira-dingtalk-notify` 已建（已带你 35 个文件的在途修复改动，按你的选择会先单独提交）。

项目摸底结论：这是个零依赖的事件驱动中台——内核只收/分/派/记，定时轮询走「cron 规则 → command 脚本 Agent → 回执 events 交回新事件（稳定 id 由内核去重）」的既有模式（`examples/recipes/github-issues`、`website-watch` 同款）；钉钉已有 webhook 文字通道（`plugins/webhook/`），但不支持加签和 @。

本功能完全复用这两条既有路径，不改协议、不加内核知识、零 Token：

```
cron */15 ──▶ watch.ts(调本地 jira MCP 查 JQL) ──回执 events(去重)──▶ 规则2
──▶ notify.ts(格式化+@手机号) ──回执 notice 卡片──▶ 钉钉 webhook 通道(加签+@白名单)
```

本地 jira MCP 已确认：`uvx mcp-atlassian==0.23.0`（stdio，Jira Cloud jira.shijidev.com，token 在 `~/.zcode/cli/config.json`，文档只写位置不抄值）。

## 改动清单

### 0. 先提交在途修复改动
把现有 35 文件按 `docs/fix-plan-2026-11-04.md` 提交成一个 commit，新功能分开提交。

### 1. `plugins/webhook/`：钉钉加签 + @ 白名单（测试先行）
- `templates.ts`：dingtalk payload 从卡片文字提取 `@手机号`，与通道配置的 `at` 白名单取交集后放 `at.atMobiles`；`isAtAll` 恒 false；新增导出 `signedUrl(url, secret, millis)`（HMAC-SHA256 加签，Node crypto，零依赖）。
- `channel.ts`：透传 `options.at`、`options.secret`。
- 安全立场不变：外部文字最多只能 @ 白名单里的人（延续 tests 里「文字不能触发提及」的既有失败模式）。

### 2. 新 recipe `examples/recipes/jira-watch/`
- `watch.ts`：command Agent。读 `jira.json`（自定义 JQL、MCP 启动命令、maxResults、jira.env 路径）；spawn MCP 子进程走 stdio JSON-RPC（initialize → `tools/call jira_search`）；回执 events：`id = KEY:updated时间戳`（稳定→内核去重，窗口重叠不重发）、type `jira.updated`、subject=issueKey、summary=标题、detail=reporter/status（资料不进提示词）、link=issue URL。带 `--dry-run` 打印 MCP 原始返回，供首次配置验证。
- `notify.ts`：command Agent。读 `AGENT_AUTOLOOP_CONTEXT` 的事件 + `users.json`（jira 账号→姓名+手机号，本地可信配置）；每条事件回执一张 notice（key=事件 id），文字含 `@手机号`（有映射才 @，无映射仅文字提名）。
- `rules.json`：规则1 `cron */15` → watcher（`emits: jira/jira.updated`，tell never）；规则2 `when source jira` → notifier（`parallel: 5` 按事项分道）。
- `README.md`：**给你的详细配置文档**——钉钉群机器人创建（推荐加签，拿 webhook+secret；关键词方式也可用）、`config.json` 通道项（url/secret/at 白名单）、`rules.json` 登记通道、`jira.env`（JIRA_URL/USERNAME/EMAIL/PERSONAL_TOKEN，chmod 600）、`users.json` 手机号映射、JQL 与 cron 间隔的搭配说明（窗口重叠靠去重）、验证步骤。
- `jira.example.json`、`users.example.json` 示例。
