# agent-autoloop 三问题处置方案

## 问题 1(worker 终态行)— 结论:不是 bug,不改代码

本机证据链已把报告的机制证伪:

- run 121 的 codex 全程在干活:`stdout-1.log` 共 512 行,`turn.started` 在第 2 行,`turn.completed` 是**最后一行**(文件 mtime 16:45:06 本地=08:45:06Z);stderr 08:44:43Z 还有工具调用记录。
- 进程 08:45:16Z 退出(`exit-1` mtime),up.log `run 121: done` 打在 08:45:16.800Z——**同一秒**。worker 没漏写,是这轮真跑了 53 分钟;你的 grep 落在运行窗口内(引用 run 125 的 context 说明报告写于 08:30~08:45 之间)。
- 全量扫描 up.log:有 started 无终态的 run 只剩 127(此刻仍在跑)。
- 代码路径核对(`worker/worker.ts` conclude/settle、`worker/contract.ts` readMessage/resultFrom):非法回执只产生 `problem`,不抛异常,必走到 `endWith → settle → run N: done|failed|cancelled|nothing`;hub 暂时收不下时也有明确中间行。验收条款「不存在 started+已退出+无终态的 run」现状即满足。

给 hunt 的建议:卡死检测别只看 started/终态差——长轮(默认上限 180 分钟)本来就没终态。用 `GET /v1/events/<编号>` 的 `runs[].state`(queued/claimed/unknown)或 `/v1/state` 更准。按仓库纪律「不补复述实现的测试」,不加测试;报告里写清结论。

## 问题 2 — PR ①(优先):规则级 `crossGroup` 开关(默认关)

语义:规则写 `"crossGroup": true` 时,它一轮的 `context.open` 和回执 `resolve` 范围从「同来源+同组+领取前」放宽为「同来源+任意组+领取前」。不写=现行为,零回归。

不采纳 `emits.cross_group_open`:emits 管"这轮能发什么事件";能结谁的卡是"这轮被信任做什么",与 cwd/权限同类,归规则本体(协议原则:文字是资料,规则才是指令)。保留 source 过滤(跨来源影响是红线)和 `created_at <= claimed_at`(领取后新开的卡不进范围,防竞态)。

改动(先写失败测试):
- `tests/cards.test.ts`:新增 ①crossGroup 规则轮 context.open 看得到别组 open 卡、回执 resolve 能结它;②crossGroup 轮也结不了领取之后新开的别组卡。现有 383 行「may resolve only what it was given to check」不动,继续锁旧行为。
- `tests/rules.test.ts`:字段校验(非 boolean 报错,用现有 `problem(change, regex)` 模式)。
- `kernel/rules.ts`:RuleOptions 加 `crossGroup?: boolean`。
- `protocol/rules.ts`:规则字段白名单加 `["crossGroup", boolean, "只能是 true 或 false", true]`。
- `kernel/query.ts`:`openInScope` 按 `run.rules_version` 查规则,置旗标就去掉 grp 过滤(jobOf 的 context.open 与 decide 的 resolve 共用它,自动一致);`jobOf` 透传。
- `protocol/job.ts`:Job rule Pick 加 `"crossGroup"`。
- `worker/contract.ts`:提示词「open 是同一组还没收尾的卡片」按 flag 换成跨组措辞(提示词里"resolve 只结 open 里列出的卡片"要求视图与可结范围一致,必须同步)。
- `docs/protocol.md`:规则字段段(~L108)、L257 context.open 描述、L302 resolve 范围,附兼容说明。

兼容影响(进 PR 正文):规则文件新增可选字段;新中台读旧规则无感;**旧中台遇到带此字段的规则文件会按「多余字段」拒收整份、旧规则继续跑——先升中台再改规则文件**(与 receipt `fyi` 字段的兼容说明同款)。回执协议、事实日志、投影格式都不变,老接单程序不用动。

## 问题 3 — PR ②(低优,docs-only):protocol.md 写清排队语义

机制已有(`GET /v1/events/<id>` 返回 `runs[].state`,queued=排队、claimed=在跑),缺的只是来源视角的一句明示。在 `docs/protocol.md` 来源段(~L147)加:`routed` 只表示规则接了;同事项已有在跑/排队的一轮会并进去,何时新开一轮由 parallel、组上限、接单程序容量决定;想知道进度拿应答里的 event 编号查 `GET /v1/events/<编号>`。不改代码、不改应答格式;纯文档 PR 按ci-scope 跳过 CI。hunt 侧照此轮询即可区分「排队中」和「丢了」。
